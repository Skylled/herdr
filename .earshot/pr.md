C — pane sizing investigation and targeted detach fix:

- Each pane has one shared terminal/PTY geometry. Clients have independent shell locations and rendered surfaces, but they do not get independent agy reflow. In `src/server/headless/client_views.rs`, `tab_geometry_controllers` selects a controlling client per tab; focus/input/navigation can claim control, and only that controller's resize drives that tab. Attaching a phone is not an unconditional smallest-client-wins rule: attach claims an unowned tab, activation/focus/input can transfer ownership. Direct `agent attach` separately resizes and locks its target terminal.
- With one active shell client, its size applies across all tabs, including background tabs (`resize_shell_tab_geometry_to_target`). With multiple clients, the owning client sizes its tab. Outer terminal chrome, sidebar, pane borders, and splits reduce the usable pane width.
- After phone disconnect: if exactly one desktop shell client remains, `remove_client_and_resize_if_needed` calls `resize_tabs_for_only_shell_client`, restoring all tabs to that desktop geometry. Existing test `client_shell_tabs_render_accept_input_and_resize_independently` characterizes this. Direct terminal-attach disconnect restores the owning shell tab's geometry; see `terminal_attach_disconnect_restores_client_shell_pane_size`.
- Confirmed root cause: `sync_foreground_client_state` resets `effective_size` to `headless_size` after a recognized last-client disconnect, but `sync_runtime_view_geometry` computes without resizing pane PTYs. `resize_tabs_for_only_shell_client` then exits at zero clients. The no-target render path also deliberately skips resizing when view geometry exists. Thus actual terminal widths can stay at 60 even though the server's fallback is 120×40. The pre-fix regression fails with actual `(24, 60)` versus expected `(40, 120)`.
- Fix: the existing shell-count geometry helper now applies configured headless geometry when there are no shell clients still connected. This covers detach, headless API layout mutations (including new tabs/splits), and config reload. Existing resize helpers include background tabs/workspaces/popups and honor direct-attach locks. No resize work was added to output parsing, input bytes, ordinary status/screen reads, or steady-state rendering, and the handoff path is unchanged.
- New-pane caveat: master already resets ViewState on a recognized detach, so its initial size estimate for a truly new pane should use the fallback. A still-registered phone connection (e.g. transport disconnect not delivered yet), a split's smaller share of the layout, or an agent launched in an existing narrow PTY can also explain narrow output. Kyle's observation is recorded evidence, but this PR does not claim to establish which of those happened at 11:50:56Z. It fixes the reproduced no-client PTY-retention defect and tests subsequent new tabs/splits. A physically disconnected peer that the transport still considers active will continue to own geometry until its disconnect is recognized.
- There is no configurable tmux-style latest/largest/manual policy. Current behavior is closest to per-tab active-controller sizing. `[server].headless_cols/headless_rows` (defaults 120×40) now restore no-shell pane geometry; they do not pin the size while an interactive shell client remains attached. Inactive shell surfaces remain attached and keep their geometry, protecting machine switching and retained-render behavior. Observer-only connections do not suppress the fallback; directly attached terminals retain their own size until they detach.
- A largest/minimum/manual geometry selector is a relatively small server-policy change, but making it pleasant for a smaller interactive client also needs deliberate crop/pan and pointer-coordinate behavior, controller/attach-lock rules, disconnect tests, and optional API/config exposure. That broader interactive policy is outside this focused detach reset. Truly independent per-client terminal reflow is substantially larger because the PTY and terminal screen are shared. Read-only `herdr terminal session observe` already avoids taking resize ownership, but does not provide an interactive phone TUI.
- Practical Termius options to try: reduce the terminal font size and rotate to landscape to increase reported columns; aim for 80–100 usable pane columns when possible, and zoom the Herdr pane or collapse its sidebar to recover space. Check `stty size` in the outer SSH shell before entering Herdr. Exact Android menus/fixed-column support were not verified on Kyle's device; current official [Termius support](https://support.termius.com/hc/en-us) did not establish a fixed-column setting, so this PR does not claim one exists. These are display adjustments, not a substitute for the width-tolerant rule.
