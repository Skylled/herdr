New tabs use the configured fallback; splitting while detached does not shrink either running terminal to its smaller layout allocation. A later attached client owns exact sizing.

C — sizing findings:

- Panes have one shared PTY geometry, not independent per-client reflow. `tab_geometry_controllers` assigns a client per viewed tab; focus/input/navigation can transfer control. A sole active shell client sizes all tabs. Multiple clients can independently size different tabs. Chrome, sidebar, borders, and splits reduce usable pane columns. Direct terminal attachment has its own resize lock.
- Before this fix, recognized final disconnect reset `effective_size` and ViewState to the headless fallback but skipped resizing actual PTYs. The no-client render path retained those PTYs. That explains the reproduced 60×24 retention. The grow-only fallback fixes narrow retention without shrinking a 160×50 desktop pane on detach or causing a second resize on reattach.
- Master already used fallback ViewState for new-pane estimates after a recognized disconnect. Kyle's new narrow pane at 11:50:56Z could additionally involve an existing narrow PTY, a split's allocation, or a transport connection still registered at the server; this PR does not establish which happened. A physical disconnect cannot affect geometry until Herdr recognizes it.
- There is no configurable tmux-style latest/largest/manual policy. Headless dimensions are configurable via `[server].headless_cols/headless_rows` (default 120×40). A largest/manual interactive policy also needs crop/pan, pointer mapping, controller rules, and tests. Independent terminal reflow is a larger change because the PTY screen is shared. Read-only `herdr terminal session observe` avoids resize ownership but is not an interactive phone TUI.
- Termius options to try: smaller terminal fonts and landscape to increase reported columns, plus zooming the Herdr pane or collapsing the sidebar. Check `stty size` in the outer SSH shell; aim for 80–100 usable pane columns when possible. Exact Android menus/fixed-column support were not verified on Kyle's device or established by current official [Termius support](https://support.termius.com/hc/en-us), so no fixed-column setting is claimed.

Remaining work: connected but inactive/frozen shell surfaces intentionally retain their geometry to preserve federated machine switching. If only inactive surfaces remain, narrow panes can stay narrow until an actual disconnect. An inactive-shell minimum-size policy is a separate follow-up; it must preserve retained views and federation behavior. This PR also does not add transport heartbeat/disconnect detection.
